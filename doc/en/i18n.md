# Languages

Spanish is the editorial source. Every strings.es.js key must appear in strings.en.js
with matching placeholders such as {n}, {total} and {piece}. Both dictionaries are
registered before app.js. Priority: ?lang, stored preference, browser language, Spanish.
Settings updates ?lang and document language. Use App.i18n.t for UI copy; data.js is
language-neutral. Switching language preserves the ongoing game and practice. Title and description change with the interface.

Run node scripts/check.js after content edits. Adding a language also requires
selector, preference validation and tests. No locale is fetched from a CDN.

New Ludia games use paired `[es, en]` content in their curriculum files.
`games/ui-strings.js` and the view adapters register shared pairs in `LudiaCopy`.
`ludia.js` uses `tr` for curriculum and `t` for shared copy. The checks validate
nonempty pairs, placeholder parity, legal exercise examples and literal UI keys.
